# Frontend Standards — Dogfood Hackathon Platform

> **The goal:** A product that looks like it was designed by a professional design team, not generated by an AI with default settings. Every decision below exists to prevent the "AI slop" aesthetic.

---

## 0. The Anti-Pattern List (Read This First)

If you are doing any of these things, **stop and fix it immediately**:

| Anti-pattern | Why it looks bad | What to do instead |
|---|---|---|
| Default blue `#3B82F6` buttons on white backgrounds | Every Tailwind tutorial looks exactly like this | Pick a custom brand color from the design tokens below |
| Cards with `rounded-lg shadow-md border border-gray-200` on white | Generic SaaS look from 2019 | Use the dark theme; use subtle glassmorphism or bold color blocks |
| Padding: `p-4` everywhere with no rhythm | No spacing hierarchy | Follow the 8px base scale strictly |
| Body text in `gray-500` on `white` | Low contrast, fails WCAG AA | Min contrast ratio 4.5:1; use the color tokens |
| `Loading...` text during data fetch | Jarring, amateur | Skeleton loaders that match the shape of real content |
| Modals without focus trapping | Accessibility failure | Use a proper dialog primitive (Radix UI / HeadlessUI) |
| `onClick={() => router.push(...)}` on a `<div>` | Breaks keyboard navigation | Use `<Link>` or `<button>` — always semantic HTML |
| Emoji in UI copy | Inconsistent, unprofessional | Use icons from Lucide React instead |
| Form errors only shown after submit | Frustrating UX | Validate on blur; show inline error immediately |
| Unstyled scrollbars, no focus rings | Feels unfinished | Style both; focus rings are required for accessibility |
| 12 different font sizes with no system | Visual chaos | Use the type scale below — nothing outside it |
| `font-size: 10px` or `font-size: 11px` anywhere | Unreadable at any size | Minimum 14px body; minimum 12px for labels |

## 1. Design System Tokens

These are the only values allowed. Do not invent new ones.

### 1.1 Color Palette

```css
/* Brand */
--color-brand-50:  #f0f4ff;
--color-brand-100: #e0eaff;
--color-brand-200: #c2d4ff;
--color-brand-400: #6b8eff;
--color-brand-500: #4f6ef7;   /* Primary action color */
--color-brand-600: #3a57e8;   /* Hover state */
--color-brand-700: #2a3fcc;   /* Active/pressed state */

/* Neutrals — dark theme base */
--color-bg-base:      #0f1117;   /* Page background */
--color-bg-surface:   #1a1d27;   /* Cards, panels */
--color-bg-elevated:  #22263a;   /* Modals, dropdowns */
--color-bg-subtle:    #2c3050;   /* Hover states, dividers */

/* Text */
--color-text-primary:   #f0f2ff;   /* Headings, important text */
--color-text-secondary: #9da3c8;   /* Body text, labels */
--color-text-tertiary:  #6b7199;   /* Placeholder, disabled */
--color-text-inverse:   #0f1117;   /* Text on light backgrounds */

/* Semantic */
--color-success:   #22c55e;
--color-warning:   #f59e0b;
--color-error:     #ef4444;
--color-info:      #3b82f6;

/* Borders */
--color-border-subtle: rgba(255, 255, 255, 0.06);
--color-border-default: rgba(255, 255, 255, 0.12);
--color-border-strong: rgba(255, 255, 255, 0.24);
```

**Rule:** Never use a hex color or Tailwind color class directly in a component. Map all colors through CSS variables or a Tailwind config that aliases them to these tokens.

### 1.2 Typography Scale

One font family: **Inter** (Google Fonts). Import weights 400, 500, 600, 700.

```
Display:  36px / 700 / letter-spacing -0.02em / line-height 1.1
H1:       30px / 700 / letter-spacing -0.015em / line-height 1.2
H2:       24px / 600 / letter-spacing -0.01em  / line-height 1.25
H3:       20px / 600 / letter-spacing 0         / line-height 1.3
H4:       16px / 600 / letter-spacing 0         / line-height 1.4
Body-LG:  16px / 400 / letter-spacing 0         / line-height 1.6
Body:     14px / 400 / letter-spacing 0         / line-height 1.6
Body-SM:  13px / 400 / letter-spacing 0         / line-height 1.5
Label:    12px / 500 / letter-spacing 0.02em    / line-height 1.4
Code:     13px / 400 / font-family: JetBrains Mono, monospace
```

**Rule:** Nothing smaller than 12px anywhere. Nothing larger than 36px except landing hero text.

### 1.3 Spacing Scale (8px base)

```
2  →  2px   (hairline — use sparingly, e.g. icon gap)
4  →  4px   (tight — icon labels, badge padding)
8  →  8px   (small — form field inner padding, list item gap)
12 → 12px   (medium — card inner gap, button vertical padding)
16 → 16px   (base — standard padding unit)
24 → 24px   (large — section content padding)
32 → 32px   (xl — between sections within a card)
48 → 48px   (2xl — between major sections on a page)
64 → 64px   (3xl — page-level vertical rhythm)
96 → 96px   (hero — very top of page only)
```

**Rule:** Every gap, padding, and margin must be a value from this list. Nothing in between (no `p-5`, no `gap-7`).

### 1.4 Border Radius

```
none  → 0
sm    → 4px    (tags, badges)
md    → 8px    (buttons, inputs)
lg    → 12px   (cards, panels)
xl    → 16px   (modals, large cards)
2xl   → 24px   (sheets, sidebars)
full  → 9999px (pills, avatars)
```

### 1.5 Shadows & Elevation

```
level-1: 0 1px 3px rgba(0,0,0,0.4), 0 1px 2px rgba(0,0,0,0.3)
level-2: 0 4px 12px rgba(0,0,0,0.5), 0 2px 6px rgba(0,0,0,0.4)
level-3: 0 8px 24px rgba(0,0,0,0.6), 0 4px 12px rgba(0,0,0,0.5)
glow:    0 0 20px rgba(79, 110, 247, 0.3)   /* brand glow for CTAs */
```

## 2. Component Standards

### 2.1 Buttons

```
Primary:   bg-brand-500 hover:bg-brand-600 active:bg-brand-700
           text-white font-semibold
           px-4 py-2.5 rounded-md
           transition-colors duration-150

Secondary: bg-bg-elevated hover:bg-bg-subtle
           text-text-primary border border-border-default
           hover:border-border-strong

Destructive: bg-error/10 hover:bg-error/20 text-error border border-error/30

Ghost:     hover:bg-bg-subtle text-text-secondary hover:text-text-primary

Disabled:  opacity-40 cursor-not-allowed (apply to all variants)

Loading:   Replace label with spinner SVG + "Processing..." — do NOT disable the button
           visually if it looks like nothing is happening
```

### 2.2 Form Inputs

```
Base:       bg-bg-surface border border-border-default rounded-md
            px-3 py-2.5 text-text-primary text-sm
            placeholder:text-text-tertiary

Focus:      ring-2 ring-brand-500 ring-offset-2 ring-offset-bg-base border-brand-500

Error:      border-error ring-2 ring-error/30
            Show error message below: text-error text-xs mt-1

Success:    border-success (after validation passes)

Label:      text-xs font-medium text-text-secondary mb-1.5
            Always use <label htmlFor="..."> — never omit
```

### 2.3 Cards

```
Base:       bg-bg-surface rounded-xl border border-border-subtle
            shadow-level-1

Interactive (hover): hover:border-border-default hover:shadow-level-2
                     hover:-translate-y-0.5 transition-all duration-200
                     cursor-pointer

Active/Selected: ring-2 ring-brand-500 border-brand-500
```

### 2.4 Badges / Status Pills

```
Structure: inline-flex items-center gap-1.5 px-2.5 py-0.5 rounded-full text-xs font-medium

registration_open → bg-emerald-500/10 text-emerald-400 border border-emerald-500/20
submissions_open  → bg-blue-500/10    text-blue-400    border border-blue-500/20
judging           → bg-purple-500/10  text-purple-400  border border-purple-500/20
voting            → bg-amber-500/10   text-amber-400   border border-amber-500/20
results_published → bg-indigo-500/10  text-indigo-400  border border-indigo-500/20
draft             → bg-gray-500/10    text-gray-400    border border-gray-500/20
archived          → bg-gray-500/10    text-gray-500    border border-gray-500/20
```

## 3. Layout & Page Patterns

### 3.1 Page Shell

```
Max content width: 1200px (max-w-screen-xl)
Page horizontal padding: px-4 (mobile) → px-6 (sm) → px-8 (lg)
Page vertical padding: py-8 (mobile) → py-12 (lg)
```

### 3.2 Navigation (Navbar)

```
Height: 60px (fixed)
Background: bg-bg-base/80 backdrop-blur-xl border-b border-border-subtle
Position: sticky top-0 z-50

Contains:
  - Logo (left)
  - Nav links (center, hidden on mobile)
  - Auth buttons or user avatar dropdown (right)
  - Mobile: hamburger menu → full-screen overlay
```

### 3.3 Grid Layouts

```
Event listing:   grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6
Submissions:     grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6
Dashboard:       grid-cols-1 lg:grid-cols-3 gap-8 (main 2/3 + sidebar 1/3)
Settings forms:  max-w-2xl mx-auto (single column, not full-width)
```

### 3.4 Empty States

Every list/table/grid MUST have a designed empty state. Not just "No data found."

```
Structure:
  Centered column: icon (40px, text-text-tertiary) + heading + subtext + optional CTA button

Examples:
  No events: "No events yet" / "Events will appear here once organizers create them."
  No submissions: "No submissions yet" / "Teams can submit projects during the submission window."
  Empty judge queue: "All caught up" / "You have no pending assignments."
```

### 3.5 Loading States

Every data-fetched section MUST have a skeleton loader. Not a spinner in the center of the page.

```
Rule: Skeletons must MATCH THE SHAPE of the real content:
  - Event card skeleton: same dimensions as event card, with pulsing bg-bg-elevated rectangles
  - Table row skeleton: same column widths as real rows
  - Profile section: circle for avatar, rectangles for name/email
  
Animation: animate-pulse (60 BPM — not too fast, not too slow)
```

## 4. Interaction & Animation Standards

### 4.1 Allowed Transitions

```
Color/background:  transition-colors duration-150 ease-in-out
Transform (hover): transition-transform duration-200 ease-out
Shadow change:     transition-shadow duration-200 ease-out
Opacity:           transition-opacity duration-150 ease-in-out
All:               transition-all duration-200 ease-out (use sparingly — expensive)
```

### 4.2 Micro-interactions

Apply these to specific elements — not globally:

```
Button press:      active:scale-[0.97] transition-transform duration-75
Card hover:        hover:-translate-y-1 hover:shadow-level-2
Icon buttons:      hover:rotate-12 (refresh icon) / hover:scale-110
Vote button:       heart fills with color on click — CSS + JS class toggle
Invite code copy:  "Copied!" tooltip appears for 2000ms then disappears
```

### 4.3 Page Transitions

```
Route change:   opacity 0→1, translateY 8px→0, duration 200ms, ease-out
Modal open:     scale 0.95→1, opacity 0→1, duration 150ms
Modal close:    scale 1→0.95, opacity 1→0, duration 100ms
Dropdown open:  translateY -4px→0, opacity 0→1, duration 150ms
```

### 4.4 What NOT to animate

```
NO continuous spinning/rotating elements on the main page
NO parallax effects
NO animations longer than 400ms for UI feedback
NO animations that cannot be disabled (respect prefers-reduced-motion)
```

Always include:
```css
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
```

## 5. Accessibility Standards (WCAG 2.2 Level AA — Mandatory)

These are not optional. A PR that fails any of these is not mergeable.

| Requirement | Standard | How to verify |
|---|---|---|
| Color contrast — normal text | 4.5:1 minimum | Use [whocanuse.com](https://whocanuse.com) or browser DevTools |
| Color contrast — large text (18px+ bold or 24px+) | 3:1 minimum | Same |
| All interactive elements keyboard accessible | Tab + Enter/Space works | Manual test — unplug mouse |
| Focus ring visible on all interactive elements | Clear ring, not hidden | Tab through the page |
| All images have `alt` text | Non-decorative images: descriptive. Decorative: `alt=""` | Code review |
| Form fields have associated `<label>` | `htmlFor` + `id` must match | Code review |
| Error messages linked to input | `aria-describedby` | Screen reader test |
| No keyboard traps (except modals, which must trap) | Can always Tab out | Manual test |
| Modals restore focus on close | Focus returns to trigger element | Manual test |
| Color is not the only indicator of state | Icon or text accompanies color | Visual inspection |

## 6. Next.js 14 Specific Rules

### 6.1 Server vs Client Components

```
Default: Server Component (no 'use client')
Add 'use client' ONLY when you need:
  - useState / useReducer
  - useEffect / useRef
  - Browser event handlers (onClick, onChange, etc.)
  - Browser-only APIs (window, localStorage)
  - TanStack Query (useQuery, useMutation)

NEVER:
  - Add 'use client' to a page.tsx just because it's "easier"
  - Wrap an entire layout in 'use client'
  - Fetch data in useEffect — fetch in Server Components instead
```

### 6.2 Data Fetching

```
Server Components:
  - Use async/await directly in the component function
  - Use Promise.all for parallel fetches
  - Cache with Next.js fetch cache or unstable_cache

Client Components:
  - Use TanStack Query (useQuery / useMutation) — no raw fetch() in useEffect
  - Enable refetchOnWindowFocus: false unless real-time data is required
  - Always show loading + error states
```

### 6.3 File Organization

```
web/src/
├── app/                    ← App Router — pages, layouts, loading.tsx, error.tsx
│   ├── (auth)/             ← Route group — login, register (no navbar)
│   ├── events/
│   │   ├── page.tsx        ← Server Component — fetches events list
│   │   ├── loading.tsx     ← Skeleton for event list
│   │   └── [slug]/
│   │       ├── page.tsx
│   │       └── ...
│   └── layout.tsx          ← Root layout with Navbar, AuthProvider, QueryProvider
├── components/
│   ├── ui/                 ← Generic reusable: Button, Input, Badge, Card, Modal
│   └── {feature}/          ← Feature components: EventCard, VoteCard, ScoreCriterion
├── hooks/                  ← useAuth, useMyTeam, useJudgeQueue etc.
├── lib/
│   ├── api.ts              ← API client (all fetch calls)
│   └── utils.ts            ← cn(), formatDate(), etc.
└── types/
    └── api.ts              ← All TypeScript types matching backend DTOs exactly
```

### 6.4 TypeScript Rules

```
NO `any` type — ever. Use unknown and narrow it.
NO non-null assertion (!) unless you can prove it is safe + add a comment
Strict mode must be enabled in tsconfig.json
All API response types must exactly match the Go backend DTOs in types/api.ts
Use discriminated unions for states: { status: 'loading' } | { status: 'error', message: string } | { status: 'success', data: T }
```

### 6.5 Error Handling in UI

```
Every useQuery() call must handle error state explicitly — no silent failures
ApiClientError from lib/api.ts contains: { code: string, message: string }
Map error codes to user-friendly messages:
  UNAUTHORIZED → redirect to /login
  FORBIDDEN    → show "You don't have permission" inline
  NOT_FOUND    → show not-found UI (not a crash)
  RATE_LIMITED → show "Too many requests — please wait" with countdown
  Others       → show generic error + retry button
```

## 7. Wireframing Process

Before building ANY new page or significant component:

1. **Sketch in Excalidraw first** — rough boxes and labels only (5 minutes max)
2. **Define the data** — what API calls does this page make? What does it display?
3. **Mark interactive elements** — what can the user click/type/submit?
4. **Get a team member to review** — even 2 minutes of "does this make sense?" prevents hours of rework

**Excalidraw setup:**
- Use the [Excalidraw VS Code extension](https://marketplace.visualstudio.com/items?itemName=pomdtr.excalidraw-editor) for in-editor wireframes
- Save wireframes to `docs/wireframes/` as `.excalidraw` files
- File naming: `docs/wireframes/{feature}-{page}.excalidraw` (e.g. `events-detail.excalidraw`)

**Do not wireframe:**
- Minor component tweaks (a new button, a different badge color)
- Layouts that already exist and just need content changes

## 8. Copy & Content Standards

```
NO emoji in UI copy — use Lucide React icons instead
NO "Click here" links — use descriptive link text
NO "Error occurred" messages — use specific messages: "Failed to load events. Check your connection."
NO "Loading..." without skeleton — skeletons are mandatory
NO all-caps text (except labels/badges) — use proper sentence case
NO exclamation marks in error messages — "Password is incorrect" not "Wrong password!"
Keep button labels under 3 words: "Save", "Submit Project", "Invite Judge"
Keep error messages under 15 words
```

## 9. Icons

Use **Lucide React** exclusively. No Font Awesome, no inline SVG emojis, no Heroicons mix.

```typescript
import { ChevronRight, AlertCircle, CheckCircle2, Loader2 } from 'lucide-react';

// Standard sizes:
// 14px — inline with text (sm)
// 16px — button icons
// 20px — section icons
// 24px — navigation
// 40px — empty state illustrations

// Always pair with aria-label when standalone (no adjacent text):
<button aria-label="Close modal">
  <X className="w-4 h-4" />
</button>
```

## 10. Performance Checklist (before every PR)

- [ ] `next/image` used for all images — no raw `<img>` tags
- [ ] No `useEffect` used for data fetching (use Server Components or TanStack Query)
- [ ] No component wrapped in `'use client'` unnecessarily
- [ ] Loading skeleton exists for every server-fetched section
- [ ] Error boundary (`error.tsx`) exists for every route segment
- [ ] `npm run build` → 0 TypeScript errors
- [ ] `npm run lint` → 0 ESLint errors
- [ ] All interactive elements keyboard-accessible (manual Tab test)
- [ ] All text meets WCAG 4.5:1 contrast ratio
- [ ] `prefers-reduced-motion` respected for all animations
